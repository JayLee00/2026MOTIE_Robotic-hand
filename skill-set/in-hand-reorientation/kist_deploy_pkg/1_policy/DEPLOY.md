## 1. 관측 링버퍼 — 깊이가 모달리티마다 다르다

`obs_spec.<모달>.{horizon, stride}` 가 100 Hz 프레임 단위 격자다. offsets = `[-(h-1)s, …, -s, 0]`.

| 모달 | horizon | stride | offsets | lookback | 필요 버퍼 |
|---|---|---|---|---|---|
| rgb | 3 | 3 | [−6, −3, 0] | 60 ms | 7 프레임 |
| state | 3 | 3 | [−6, −3, 0] | 60 ms | 7 프레임 |
| **tactile** | 3 | **10** | **[−20, −10, 0]** | **200 ms** | **21 프레임** |

- **왜 촉각만 200 ms 인가**: 12-D F/T 는 양자화 0.1 N 인데 활동범위가 0.2~0.4 N 이라 축당 2~4단계다.
  60 ms 창에서는 **채널의 83.9% 가 값이 안 변한다**(실측). 창을 늘리면 선형 프로브의 액션 예측이
  모든 신호 계열에서 **단조로 좋아졌다**(done_v4 §2B). ManipForce 도 힘 8샘플 : 이미지 2샘플이다.
- **학습 때 창 생성 규칙**: 데모의 `t` 는 `back = max(모든 모달의 lookback)` 부터 시작한다.
  즉 촉각을 켜면 **첫 20 프레임은 학습에 쓰이지 않았다**. 배포도 같아야 한다.
- **RGB 는 과거에서만 가져온다.** 학습에서 `40_image == -1`(카메라 늦게 켜짐) 구간은 윈도우 생성
  단계에서 제외했다. 배포에서 프레임이 아직 없으면 **추론을 미루는 것**이 맞고, 최신 프레임을
  당겨 쓰면 학습에 없던 조합이다.

## 2. RGB

```
640×480 JPEG → crop(left,upper,right,lower) = [71, 0, 551, 480]   # 480×480 정사각
             → resize (224, 224) BILINEAR
             → uint8 → float32 / 255.0        # [0,1] 범위로만!
```

- ⚠️ **ImageNet 정규화는 인코더 안에서 한다**(`vtdp/encoders.py _VisionBase._pre`).
  미리 정규화해서 넣으면 **이중 적용**이다. `[0,1]` float 을 그대로 넣어라.
- 정사각 크롭을 하는 이유: 640×480 을 224² 로 바로 누르면 종횡비가 4:3 → 1:1 로 찌그러져
  **원형 과일이 타원이 된다**. done_v1 이 그 상태로 학습했다.
- ⚠️ **crop 좌표는 이 카메라 위치 전용이다.** 카메라를 옮기면 무효 — 재수집·재학습이다.
  (학습 데이터에서 레몬이 u∈[229,351] 에만 나타나 이 크롭으로 손실이 0 이었다.)
- `frozen: true` + `norm: auto` → **BN 이 eval 로 고정된 채 유지된다**(GN 치환 ❌ — GN 치환은
  파인튜닝용이고 얼린 backbone 에 쓰면 feature 가 죽는다). 따라서 **`policy.eval()` 필수**.

## 3. 촉각 — 승자 arm 에 따라 달라진다 (`tools/best_model.py` 가 확정한다)

공통: 레이아웃은 **부위-major**. `x[..., p*ch + c]` 가 부위 p 의 채널 c, `n_part = 4`.
raw 는 `reshape(n, 4, 127, 3)` = [부위, 탁셀, xyz] (드라이버 `tactile_uart.py` 의 디코드와 동일).
⚠️ 이 순서를 잘못 잡으면 **조용히 엉뚱한 손가락을 학습·추론**한다.

### 3-1. `transform: hp` — 인과적 EMA 고역통과 🔴

```
m[0] = x[0]
m[t] = m[t-1] + (1/τ) · (x[t] - m[t-1])      # τ = 100 프레임 = 1.0 s @100Hz
y[t] = x[t] - m[t]
```

- **왜 필요한가**: 데모의 절반에서 촉각 부위가 얼어붙어 있고, 그 상수값이 데모마다 달라서
  정규화 단위로 0.46~0.99 σ 짜리 **"데모 신원 꼬리표"** 가 된다. 전 데이터를 합치면 std≠0 이라
  **정규화의 상수채널 안전장치에 안 걸린다.** 정책은 그 꼬리표를 창당 상수로 읽는다.
  고역통과는 **데모 안에서 정확히 상수인 채널을 정확히 0** 으로 만들어 그 꼬리표를 지운다.
- **왜 마스킹이 아니라 이것인가**: 부위 생사를 판정해 마스킹하려면 데모 전체를 봐야 한다 =
  **배포에서 미래를 본다.** 고역통과는 인과적이라 실기에서 그대로 돈다.
- 🔴 **배포 구현 규칙**
  - EMA 상태를 **에피소드 하나 동안 끊김 없이** 유지한다. 윈도우·추론 스텝마다 초기화 ❌.
  - 학습에서는 데모 **첫 프레임부터** 굴렸다. 배포도 **잡기 시작 전부터** 센서를 읽으며 굴려라.
    (τ=1 s 이므로 최소 ~1 s 는 예열이 필요하다.)
  - float32 로 충분하다 — `x[t] == m[t-1]` 이면 차가 정확히 0 이라 상수 채널은 정확히 0 을 유지한다.
  - **설계된 강건성**: 배포 중 부위가 죽어도 그 채널은 정확히 0 이 되어 **학습 때 본 분포와 같다.**

### 3-2. `transform: [rawstat, hp]` — raw 1524 에서 접촉 통계 28칸

`11_hand_paxini_raw` (1524) → `reshape(n,4,127,3)` → 부위별 7칸:

| 칸 | 정의 |
|---|---|
| 0–2 | 127탁셀 **벡터합** (x, y, z) — 드라이버 `tactile_resultant_ft()` 와 같은 연산 |
| 3 | 접촉 탁셀 수 = `#{ ‖(x,y,z)‖ > θ }`, **θ = 0.1** |
| 4 | 최대 탁셀 크기 |
| 5–6 | 접촉 탁셀 **index 의 크기가중 평균·표준편차** |

- **왜 벡터합만 쓰면 안 되는가**: 단순 벡터합(`rawsum12`)은 오히려 12-D F/T 보다 **나쁘다**
  (선형 프로브 −1.55% vs −3.24%) — 127 탁셀을 더하면 서로 반대편을 누르는 접촉이 상쇄된다.
  접촉 분포 통계를 붙여야 −4.37% 로 역전한다(done_v4 §2B).
- **θ=0.1 의 근거**: 탁셀 크기 백분위 실측에서 p50=p75=**0.0**, p90=0.3464(= 축당 0.2 양자화 한 칸).
  즉 θ=0.1 은 "0 이 아닌 탁셀을 전부 접촉으로 센다"는 뜻이다.
- ⚠️ **index 모멘트는 탁셀의 물리 좌표표가 없어서** 배열 순서를 물리 순서로 가정한 값이다
  (그래서 `taxel_cnn` 을 폐기했다). 드라이버 배열 순서가 바뀌면 이 두 칸의 의미가 바뀐다.
- ⚠️ **raw 를 쓴다고 고장이 사라지지 않는다.** `ft` 가 죽은 자리에서 raw 가 사는 비율은
  레몬 part3 25/26 · **part1 은 7/19**(12 데모는 raw 도 정확히 0 = 진짜 사망)다.

## 4. 정규화 — 재계산 금지

- `ckpt['obs_norm']` = 모달별 `{mean, std, const_idx}` (state·tactile). `ckpt['act_norm']` = 액션용.
- **train split 프레임만으로** 적합됐다. 배포 데이터로 다시 적합하면 다른 자가 된다.
- **상수 채널은 std=1** 이다. `1e-6` 로 클립하면 배포에서 **10⁶배 폭발**한다(루트 `CLAUDE.md` 불변식).
- RGB 는 `Normalizer` 대상이 **아니다** — ImageNet 정규화가 인코더 안에 있다(§2).

| 명령 공간과 측정 공간을 섞었다 | `JOINT_LIMITS` 는 **명령** 봉투인데(학습 액션 위반 **0/101,660**) 앵커를 **측정값**에 걸었다. 측정은 35.4% 가 봉투 밖(j5 최대 8018 count) → 첫 틱에서 속도 클램프가 놀고 `np.clip` 만 값을 옮겨 **속도 상한을 통째로 우회** | 앵커·램프 시작점을 `clip(측정, 한계)` 로 |

오프라인 `_tick` 복제로 수정 전/후 대조(첫 발행 `|target−j_pos|` / 램프계수 / 직전타겟 대비 step):

| 시나리오 | 수정 전 | 수정 후 |
|---|---|---|
| 문서 절차(예열 후 발판) | 0 / 0.00 / 0 | 0 / 0.00 / 0 |
| latched engage · 손 표류 500 count/s | **475** / 0.68 / 200 | **0** / 0.00 / 0 |
| 카메라 3 s 지연 · 표류 500 count/s | **1340** / **1.00(램프 소멸)** / 160 | 500 / 0.00 / 0 |
| j5 글리치 8018 (한계 0~4096) | 3922 / — / **step 3922 = 상한 200 의 20배** | 3922 / 0.00 / **step 0** |

(수정 후에도 남는 `|Δ|` 는 **측정이 명령 봉투 밖인 만큼**이다 — 명령은 봉투 안에서 출발할
수밖에 없다. 중요한 건 직전 타겟 대비 step 이 상한 안이라는 것.) 수정 후 재생 MAE 404.1 = 무회귀.

🔴 **GPU 경합 주의.** 학습이 같이 돌던 동안 추론은 **p50 100~139 ms** 였다(20 Hz 예산 50 ms 초과).
`exec_horizon 16` 이라 800 ms 마다 한 번이라 버텼지만 액션 스트림이 간헐적으로 굶었고(`buf=0`)
MAE 가 402 → 526 으로 밀렸다. **실기 돌리기 전에 학습을 멈출 것.** 진단은 `--self_test` 가
알아서 찍는다(`nvidia-smi` 의 다른 프로세스를 같이 출력한다).

유휴 GPU 실측(같은 ckpt·같은 코드): `--self_test` **p50 12.5 / p90 12.7 ms**(계산만),
ROS 루프 안에서는 **p50 41 ms** — 차이는 GPU 가 아니라 **CPU·GIL 경합**이다(30 Hz JPEG 디코드
5.7 ms/장 + 100 Hz 발행 + `torch.set_num_threads(1)`). 예산 안이지만 self_test 숫자만큼
여유가 크진 않다. 부족하면 `--ddim_steps 4`(아래).

**학습을 못 멈추면 `--ddim_steps 4`.** §6 이 지목한 "유일하게 큰 손잡이"를 실측했다 —
경합 상태에서 추론 p50 **100 → 44.6 ms**(예산 안), 품질 비용은 **없다**:

| ddim_steps | 10 | 6 | 4 | 2 |
|---|---|---|---|---|
| 홀드아웃 3데모 MAE [count] | 390.1 | 389.7 | **386.2** | 393.8 |

폭 2%(=7.6 count)는 σ_run 1.61~2.08% 와 같은 자릿수라 **구분되지 않는다**. 즉 10 스텝은
지금 공짜로 지출되고 있다. (n=660 스텝 · 샘플링 seed 1개 — 정밀 비교가 아니라 "손해 없음" 확인.)

### 계획에 없던 소득 2건 — 둘 다 정책이 open-loop 재생이 아님을 보인다

| 관찰 | 무엇을 배제하나 |
|---|---|
| **레몬이 카메라 화면에 안 보이면 손을 돌리지 않는다** | **궤적 암기가 아니다.** 인게이지만 되면 학습 궤적을 무조건 재생하는 정책이라면 물체 유무와 무관하게 돌아야 한다. 시각 조건화가 실제로 작동한다 |
| **레몬이 손 안에서 중심에서 벗어나면 엄지로 되끌어와 중앙에 놓는다** | **feed-forward 가 아니다.** 학습 데이터에 없던 상태에서 교정 동작이 나온다 = 관측→액션 폐루프가 산다 |

두 관찰 모두 홀드아웃 MAE 가 **못 재는 것**이다. J_demo 는 "사람 궤적과 얼마나 닮았나"만
재므로, 물체가 없을 때 멈추는 능력도 벗어난 물체를 되끌어오는 능력도 그 자에 안 잡힌다.
**실기가 오프라인 자보다 많은 것을 말해 준 첫 사례다.**

🔴 **단, 둘 다 *시각* 조건화의 증거지 촉각 기여의 증거가 아니다.** 데모 주장
(*시각 only < 시각+촉각*)은 이 rollout 으로 전진하지 않았다 — 같은 두 동작이
`m2_mdrop_v`(시각-only, J_demo 401.15)에서도 나오는지 **대조를 돌려야** 말할 수 있다.

📌 중심 복귀는 **낙하 회복이 아니다** — 손 안에서 벗어난 것을 되끌어온 것이고, 낙하 회복은
